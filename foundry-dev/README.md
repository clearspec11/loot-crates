# Checking against a real Foundry world

`headless/run.cjs` joins a world as its Gamemaster in headless Chromium and runs a script as an async function body in the page, printing its return value as JSON. `headless/serve-module.py` serves this checkout's `module/` folder with CORS so the script can `import(MODULE_BASE + "scripts/x.js")` and test the working copy without installing anything on the Foundry host.

```
python3 foundry-dev/headless/serve-module.py module 8766 &
FOUNDRY_URL=http://192.168.0.57:30000 MODULE_BASE=http://<this machine>:8766/ \
  NODE_PATH=$(npm root -g) node foundry-dev/headless/run.cjs foundry-dev/checks/live-pull.js
```

Needs Playwright with Chromium 146 or newer (Foundry v14 refuses older) and a Gamemaster with no password: a dev world only. `checks/live-pull.js` does one real purchase on a test actor in the "Loot Crates Test" folder and reports the purse and the granted item. `checks/live-refund.js` does one pull at a fractional price, writes the log row, refunds it with `refundPull`, and reports that the purse is back to the same copper in whole coins, the granted item is gone, the box's stock is restored, and a second refund changes nothing. `checks/live-reveal.js` plays the reveal window with a strip built from the items compendium, writes nothing, and reports how far the landed card sits from the marker (`--shot` for a screenshot). `checks/live-missing.js` saves a test pool with one legendary entry pointing at a dead UUID, buys one crate through the GM's socket path, and reports the odds before and after (legendary gone), that the purse was charged once, and that the pool setting now flags the dead entry `missing: true`. It then opens the manager and reports the pool editor's rows: dead entries show "Source missing" (one the last sweep hadn't seen is flagged by the render), stale names show "was <old name>" with Update, the Boxes tab's odds leave the dead entries out, Update copies the source's name, and an item dropped on a missing row relinks it with its weight kept (`--shot` shows the pool). `checks/live-drop.js` makes sure an Item folder "Loot Crates Test" holds two test items, runs `entriesFromDrop` on the dnd5e.items compendium, that folder and a dnd5e.tables roll table, adds the first two to a test pool and reports the entries added; it then drops the folder on a second pool in the manager and clicks Add in the preview, drops the compendium and leaves its preview open (`--shot` shows it), and lists the packs the compendium picker offers. `checks/live-edits.js` makes no purchase: it opens the box editor, takes one from stock through the write queue while the dialog is open and saves a new price (stock stays lowered), opens a pool's rename dialog while a sweep flags its dead entry (the flag survives the rename), and relinks that entry with its Relink button and a typed UUID (weight kept).

Rules for the dev world: test actors only in that folder, never delete anything, never touch other folders' actors.
